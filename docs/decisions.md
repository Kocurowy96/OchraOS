# Decision log

Short record of what was decided and why. Newest first.

| Date | Decision | Why |
| --- | --- | --- |
| 2026-11-23 | ABI target Linux 6.12: `uname` reports `Linux`, release `6.12.0-ochra`, version `OchraOS <version>`; unimplemented syscalls return `ENOSYS` | programs check the system name and kernel version; the suffix and the version field still say what runs |
| 2026-11-23 | Directory reading (`getdents64`), terminal control (termios), Ctrl-C and job control move to stage 3 | they belong with the VFS and a real `/dev`; stage 2 runs scripts and a plain interactive shell |
| 2026-11-23 | Signals as in Linux: per-process actions, mask and pending set; delivered on every return to user mode through a hook `ochra-frame` calls after syscalls, interrupts and exceptions; handlers get Linux's `rt_sigframe` (registers, `fxsave` state, `siginfo`, `ucontext`) on the user stack and come back through `sa_restorer` and `rt_sigreturn`; a blocked syscall gives up with `ERESTARTSYS`/`ERESTARTNOHAND`, and the return hook restarts it or turns it into `EINTR` (`SA_RESTART`) | the C library and programs depend on this exact ABI; one place decides delivery and restarts |
| 2026-11-23 | Simplified for now: real-time signals are not queued (one pending per number, like standard ones); stop signals are ignored by default (no job control); no `sigaltstack`; every process may signal every other (no users yet) | enough for busybox `sh`; each comes with the feature that needs it (threads, job control, users) |
| 2026-11-23 | CPU faults with a blocked or ignored signal still end the process (Linux's `force_sig`); init gets no signal it has no handler for; a parent that ignores `SIGCHLD` (or sets `SA_NOCLDWAIT`) gets no zombies | as Linux |
| 2026-11-23 | BusyBox 1.38.0 from Git, pinned to commit `fc71374d`; `userspace/busybox.config` lists only the options set on top of `allnoconfig` (merged by `cargo xtask`, then `make oldconfig`; the build fails if an option does not stay); static, linked against our musl through a small generated compiler wrapper; no build timestamp | the configuration is short and readable; reproducible binary; P2's decision kept "only the configuration in the repository" |
| 2026-11-23 | `/init` is a shell script (`#!/bin/sh`): the kernel's `execve` runs `#!` scripts as Linux does (interpreter, optional argument, script path; 4 levels at most); applets are symbolic links to `/bin/busybox` | the usual initramfs layout; scripts and links are what busybox and later init systems expect |
| 2026-11-23 | The initramfs keeps directories, symbolic links (resolved with `.`, `..`, at most 40 links) and character device nodes; `/dev/null` (1:3) and `/dev/console` (5:1) are nodes in the archive; read-only (writing gives `EROFS`); each process has a current directory | busybox needs `/dev/null` and path lookups; device nodes in the cpio are how Linux's initramfs does it; the VFS (stage 3) replaces it |
| 2026-11-23 | Slots of freed kernel stacks are reused | otherwise every 32 new tasks needed a new page table that was never freed |
| 2026-11-23 | The user-program tests also check that the kernel heap does not grow between rounds | caught two leaks: the forked child's saved registers and the process record (both held across a function that never returns) |
| 2026-11-22 | Scheduling states (running, ready, sleeping, blocked, exited) change only under the run queue lock; a waiter marks itself "sleeping" before re-checking its condition, and a wake-up in that window cancels the block; `WaitQueue::wait_until` re-checks after every wake-up | no lost wake-ups from another CPU or an interrupt; idle tasks never block, so a CPU always finds a task |
| 2026-11-22 | An exiting task is freed by the next task on its CPU (per-CPU "reaped" slot); kernel stacks are unmapped and freed with a shootdown on every CPU (kernel pages are global, so `invlpg`, never a CR3 reload) | a task cannot free the stack it runs on; frames must not be reused while another CPU may still cache them |
| 2026-11-22 | Processes in one global table; a process that exits releases memory and files at once and stays a zombie until `wait4`; its children go to init, or are collected by the kernel when there is no init (user-program tests); init ending is a kernel panic | Linux semantics; the global lock is simple and enough until there are many processes |
| 2026-11-22 | Unix file model: `File` (the object), `OpenFile` (shared by `dup`/`fork`, holds `O_NONBLOCK`), per-process `FdTable` with close-on-exec; pipes hold 64 KiB, writes up to `PIPE_BUF` (4096) are atomic; a write without readers gives `EPIPE` (no `SIGPIPE` until signals, P4) | as Linux; closing the last descriptor drops the object, which is how a pipe learns its other end is gone |
| 2026-11-22 | Console input in canonical mode (echo, Backspace, Ctrl-U, Ctrl-D, CR to LF), polled from COM1 on the boot CPU's timer tick; termios `ioctl`s later | enough for an interactive shell; no UART interrupt wiring yet |
| 2026-11-22 | `vfork` is implemented as `fork`; `clone` only in its plain `fork` form (`SIGCHLD`, no new stack) until threads (stage 4) | POSIX allows `vfork` to be `fork`; correct programs only `execve` or `_exit` after `vfork` |
| 2026-11-22 | Stack guard gap of 256 pages (1 MiB) below the stack's 8 MiB room, kept free from `mmap`; `mmap` uses a free hint anywhere in the user half | Linux's `stack_guard_gap` against Stack Clash |
| 2026-11-22 | The user-program tests read the program's stdout through a real pipe until end of file (stdin empty, stderr the console), as `cargo xtask test` does on the host; `/init` is a small C program until busybox (P4) that runs `/bin/hello` and echoes console lines, and the boot test types into the serial port | the same conditions on both sides; console input tested end to end |
| 2026-11-22 | W^X stays the default for processes; writable+executable memory is an exception granted per application by Ochra Guard with the user's consent (like macOS `allow-jit`), with ready profiles for Wine/Proton and the JVM; implemented with Wine (stage 7) | JIT compilers need it, Windows programs often ask for `PAGE_EXECUTE_READWRITE`; everything else keeps the protection |
| 2026-11-22 | CR4.OSXSAVE stays off until task switches save the extended state with `xsave` (AVX) | with it on, programs would use AVX registers that `fxsave` does not save, corrupting and leaking them between processes |
| 2026-11-22 | x87/SSE registers enabled for user programs (CR4.OSFXSR) and saved eagerly with `fxsave`/`fxrstor` on every task switch; AVX (`xsave`) later | the x86-64 Linux ABI uses SSE everywhere (musl, gcc); eager saving is simple and safe on SMP; the kernel itself stays soft-float |
| 2026-11-22 | User memory is W^X for now: ELF segments that are writable and executable give `ENOEXEC`, `mmap`/`mprotect` with `PROT_WRITE` and `PROT_EXEC` together give `EACCES` (as Linux with SELinux denying `execmem`) | no writable code in processes; JIT compilers (later Wine, browsers) will need an explicit way around it, to be decided then |
| 2026-11-22 | Process memory: a set of reserved ranges ("areas") per process, permissions only in the page tables; anonymous `mmap`, `brk` and ELF segments allocated eagerly (zeroed frames); `PROT_NONE` pages keep their frame in a not-present entry (software bit 9); the stack (8 MiB limit) grows on demand on a page fault, also when a syscall writes to it | simple and enough for static programs and busybox; lazy allocation and copy-on-write come later |
| 2026-11-22 | ASLR follows Linux's x86-64 ranges: PIE base at 2/3 of the user half plus 28 random page bits, stack top minus 22 bits, mmap base below the stack gap minus 28 bits, `brk` up to 32 MiB past the program, stack shifted by up to 8 KiB | addresses look familiar in a debugger; same entropy as Linux |
| 2026-11-22 | The initramfs is the first Limine module; a malformed archive is ignored with an error; `/init` (or `rdinit=`) is started with `HOME=/` and `TERM=linux`, as Linux does | same conventions as Linux, so busybox and later init systems work unchanged |
| 2026-11-22 | Syscall test programs run with `test=usertests` (selftest builds only), one at a time with stdout captured; the kernel logs exit status and output in hex, and `cargo xtask test` compares both with the same binary run on the host (argv[0] = initramfs path, empty environment) | the Linux ABI checked against Linux itself, not against expectations written by hand |
| 2026-11-22 | User address spaces copy the kernel's 256 upper PML4 entries; the kernel half gets all its PML4 entries at boot (heap, stacks, devices pre-created) and never a new one after | every process shares the same kernel tables without updating them later |
| 2026-11-22 | TLB shootdown: one request in flight, sent by IPI only when the address space is in CR3 on another CPU; a waiting CPU keeps answering requests; never called under a lock; dropping an address space needs none (no CPU has it loaded, no PCIDs) | correct without deadlocks between CPUs shooting down at the same time; cheap for single-threaded processes |
| 2026-11-22 | Syscalls, interrupts and exceptions share one register frame and one way back to user mode, always `iretq` (never `sysret`); a return address in the kernel half becomes the program's own #GP | rules out the `sysret` non-canonical RIP bug (CVE-2012-0217); `sysret` can come back with profiling |
| 2026-11-22 | The safe kernel crate registers a syscall handler and a fault handler and sees user registers only through `UserContext` (no access to CS, SS, RFLAGS) | policy stays in safe code; it cannot make the return to user mode fault in the kernel |
| 2026-11-22 | User memory only through `copy_from_user`/`copy_to_user`: range checked against the user half, SMAP opened with `stac`/`clac` for the copy alone, interrupts off per 4 KiB chunk, faults caught through a fixup table of relative offsets (`EFAULT`, never a panic) | interrupts do not clear AC, so a handler would otherwise run with SMAP open; relative entries need no relocations in the PIE kernel |
| 2026-11-22 | musl (MIT) and busybox (GPL-2.0) are built from Git sources pinned to a commit by `cargo xtask`, like Limine; only busybox's `.config` lives in the repository | Linux userspace to test the ABI with; no binaries in the repository |
| 2026-11-22 | Syscall test programs are written in C against musl; each prints only deterministic output, which is compared with the same program run on the host Linux | Linux is the spec, checked by machine; no `unsafe` user-space Rust outside `frame` |
| 2026-11-22 | `fork` copies the whole address space at first; copy-on-write later, when profiling asks for it | simple and obviously correct; busybox processes are small |
| 2026-11-22 | Console input polls COM1 on timer ticks until the I/O APIC arrives (with ACPI, alongside the first real driver) | no ACPI parsing yet; CI needs no input |
| 2026-11-22 | Until the VFS (stage 3): a read-only initramfs filesystem, the console and pipes behind one small file interface | enough for busybox `sh`; the real VFS replaces it |
| 2026-11-22 | User-space ASLR (stack, `mmap` base, static-PIE load address) from stage 2, randomness from an own ChaCha20 CSPRNG in `frame` seeded from RDRAND, RDSEED and the TSC, after CPUID and sanity checks | cheap next to KASLR; one vetted source of randomness instead of raw RDRAND (AMD once returned all ones) |
| 2026-11-22 | KPTI is not implemented yet; required before running on a Meltdown-affected CPU (detect `RDCL_NO`) | QEMU and later hardware first; recorded in `security.md` so it is not forgotten |
| 2026-11-22 | SMP scheduling: one global run queue for all CPUs, one idle task per CPU; every task has an `on_cpu` flag (as in Linux), cleared by the context switch only after the task is saved and its stack left, and a CPU waits for it before running the task | simplest correct design; a task put back into the queue cannot be started twice; per-CPU queues with work stealing can come when profiling asks for them |
| 2026-11-22 | TLB shootdown is deferred to stage 2: the kernel only adds mappings so far, and the CPU never caches non-present entries | no stale translations can exist until something is unmapped (process address spaces) |
| 2026-11-22 | Every CPU runs its own local APIC (mode chosen once on the boot CPU, mode bit set per core) and its own periodic timer; the timer is calibrated once against the PIT, on the boot CPU, before the APs start | one PIT to measure with; all cores share the timer clock |
| 2026-11-22 | A panic or fatal exception stops the other CPUs with an NMI ("all excluding self"); they confirm, and the report says how many stopped; a second crashing CPU halts quietly | an NMI also reaches CPUs spinning with interrupts off; nothing runs on after a crash |
| 2026-11-22 | SMP: APs are started by Limine (MP request), not by an own INIT-SIPI-SIPI trampoline; CPUs get logical indexes (boot CPU 0) | no 16/32-bit start-up code and far less `unsafe`; Limine leaves every AP in 64-bit mode |
| 2026-11-22 | Per-CPU data through the GS base (`gs:[0]` holds the structure's own address), allocated on the heap per CPU (no `MAX_CPUS`); read only with interrupts off | one instruction to find it; the same mechanism `swapgs` needs for syscalls in stage 2 |
| 2026-11-22 | Every CPU has its own GDT and TSS (a loaded TSS is busy and cannot be shared) and its own double fault stack with a guard page; the IDT is shared | the TSS holds per-CPU interrupt stacks; the IDT never changes |
| 2026-11-22 | The crash-report writer takes the COM1 lock if it comes free within a bounded spin, and keeps it | the report is not mixed with other CPUs' lines; a lock held by the crashed code itself does not block it |
| 2026-11-22 | QEMU runs with `-smp 4` for `run` and `test`; one test boot uses `-smp 1` | SMP code is always exercised; single-CPU machines keep working |
| 2026-11-22 | Scheduling split: the mechanism (task stacks with guard pages, context switch, current task) in `ochra_frame::task`, the policy (round-robin run queue, switch on every timer tick) in the safe `kernel` crate | the policy can change without new `unsafe`; the context switch saves only callee-saved registers, the interrupt path saves the rest |
| 2026-11-22 | End-of-interrupt is sent before the interrupt handler runs (interrupts stay off until `iretq`) | a handler may switch tasks and not return for a while; the APIC must not wait for it |
| 2026-11-22 | After boot the kernel only runs tasks: an `idle` task (`sti; hlt` loop) replaces halting; tasks do not exit yet | the boot stack (no guard page) is left for good; task exit comes with processes in stage 2 |
| 2026-11-22 | Interrupts: legacy PIC remapped to 32–47 and masked; local APIC in x2APIC mode, xAPIC (MMIO, uncached mapping in PML4 slot 510) as fallback; timer vector 0x30, spurious 0xFF; all `frame` locks are `IrqMutex` (interrupts off while held) | modern interrupt path only; no same-CPU deadlock between a lock holder and an interrupt handler |
| 2026-11-22 | Timer: LAPIC timer in periodic mode at 100 Hz, calibrated over 10 ms with PIT channel 2 | the PIT has a known frequency on every PC; 10 ms is a reasonable first time slice; TSC-deadline can replace it later |
| 2026-11-22 | Kernel heap: own first-fit free list sorted by address, merging neighbours, 16-byte granularity, in PML4 slot 508, grows on demand; no allocator crate | simple to read and verify; size classes can come later if profiling asks for them |
| 2026-11-22 | Kernel virtual layout: image in slot 511 (KASLR), direct map at Limine's random offset, heap slot 508, kernel stacks slot 509 in 64 KiB slots (guard page below each); checked at boot | fixed, documented regions; the guard pages cost no memory |
| 2026-11-22 | Physical frames are owned `Frame` handles (no Copy, freed on drop), as in Asterinas | safe kernel code cannot double-free or use a frame after freeing it |
| 2026-11-22 | Kernel is a PIE again, `kaslr: yes` in `limine.conf` (Limine also randomises the direct map base); one switch `ochra_frame::SHOW_ADDRESSES` (debug builds) gates every address in the log and crash reports | ends the temporary static build; a single RIP in a breakpoint message or a crash report would reveal the offset just as well as the explicit base |
| 2026-11-22 | Claude runs `git commit -s` and `git push` at pitstops; each run is approved by the owner in a permission prompt (or explicitly in chat when no prompt appears) and the signature in the SSH agent | the owner's approval of that exact commit is the DCO certification; no `--amend`, force push, `--no-verify` or disabled signing unless asked |
| 2026-11-22 | Working mode from stage 1: steps without stopping, pitstops with fmt/clippy/test, report, journal and commit | the owner reads code as it lands; stops only for new design decisions, dependencies, unfixable test failures, rules/licences/security |
| 2026-11-22 | Kernel entry: `ochra-frame` owns `kmain` and calls `__ochra_kernel_main`, defined by its `entry!` macro in the kernel; `cargo xtask check-unsafe` rejects `unsafe` in code of every crate except `frame` | `kernel` can be `forbid(unsafe_code)` although the dependency points the other way; the text check backs up the lint, which skips code from external macros |
| 2026-11-22 | SMP is a separate mini-stage 1.5, after stage 1 "Done when" and before stage 2 | stage 1 stays focused on one core; everything is still designed for SMP |
| 2026-11-22 | `ochra-frame` is licensed GPL-2.0-only, like the rest of the kernel | it is part of the kernel; no plan to offer it to other projects |
| 2026-11-22 | Low-level crate named `ochra-frame`, in `frame/` | "framekernel" (as Asterinas OSTD): all low-level `unsafe` in one crate, the rest of the kernel is safe Rust |
| 2026-11-22 | DCO check in CI has no exception for bots: Dependabot commits are amended with `git commit --amend -s` by the owner before merging | only a human can certify the DCO; one strict rule is easier to trust than a list of exceptions |
