# 2026-11-24

## Stage 3, P2: terminals, job control, poll, /proc and /sys (pitstop P2)

P1 (`f3a377b`) was pushed and green in CI at the start of the session. The owner accepted the
P2 plan, with ptys (`/dev/ptmx`, devpts), `/proc` and `/sys` mounted by the kernel, and
`/dev/console` never becoming a controlling terminal by `open`. Additions from the owner's
security review: no `TIOCSTI`, a `ptrace_may_access`-style check for other processes'
`/proc` files, no kernel addresses in `/proc`, and `poll` registering before it checks.

### Done

- Terminals (`kernel/src/tty/`): one line discipline as Linux's N_TTY — canonical mode with
  ERASE, WERASE, KILL, LNEXT, REPRINT, EOF, EOL; raw mode with VMIN/VTIME; echo with
  ECHOCTL/ECHOE/ECHOK/ECHOKE/ECHONL; ICRNL/INLCR/IGNCR/ISTRIP; OPOST/ONLCR/OCRNL/OLCUC;
  IXON/IXANY; ISIG with NOFLSH; TOSTOP. The ioctls: `TCGETS`/`TCSETS*` (and the `termios2`
  ones), window size, `TIOCGPGRP`/`TIOCSPGRP`, `TIOCSCTTY`, `TIOCNOTTY`, `TIOCGSID`,
  `FIONREAD`, `TIOCOUTQ`, `TCFLSH`, `TCXONC`, `TIOCEXCL`, `TIOCGDEV`; `TIOCSTI` is `EIO`.
- Drivers under it: the serial port (`/dev/ttyS0`, also `/dev/console`, still polled on the
  timer tick), and pseudo-terminals: `/dev/ptmx`, slaves locked until `unlockpt`, devpts on
  `/dev/pts`, hangup both ways as Linux (the slave reads 0 and writes `EIO`; the master reads
  `EIO` and polls `POLLHUP`). `/dev/tty` is the controlling terminal. `console.rs` is gone.
- Sessions and groups: `setsid`, `setpgid`, `getpgid`, `getsid`; controlling terminals
  acquired as in Linux; a session leader's exit sends `SIGHUP` to the foreground group.
- Job control: stopped processes, `SIGSTOP`/`SIGTSTP`/`SIGTTIN`/`SIGTTOU`/`SIGCONT`,
  `WUNTRACED`/`WCONTINUED`, `CLD_STOPPED`/`CLD_CONTINUED` and `SA_NOCLDSTOP`; background
  reads and writes (with TOSTOP) and settings changes get `SIGTTIN`/`SIGTTOU`; orphaned
  groups get `SIGHUP`+`SIGCONT` and are not stopped by terminal stop signals.
- Fixed a P1 bug in the path walk: after a symbolic link in the middle of a path, the rest
  of the path was walked before the link's target (`/proc/self/stat` looked for `stat`
  in `/proc`). The earlier tests only had links at the end of a path; `files` now has one
  in the middle.
- `ERESTART_RESTARTBLOCK` and `restart_syscall`: a `sleep` stopped with Ctrl-Z and continued
  with `fg` sleeps on (the first boot test found it returning early).
- `poll`, `ppoll`, `select`, `pselect6` on `sched::wait_any`: the task is put on every wait
  queue before any file is checked. Files say what wait queues they use (`File::wait_queues`)
  and what is ready (`File::poll`). `ioctl` goes to the file; `FIONBIO`, `FIOCLEX`,
  `FIONCLEX` are answered for any descriptor.
- Synthetic filesystems (`kernel/src/fs/synthetic.rs`) and on them procfs (`self`,
  `<pid>/{stat,status,cmdline,environ,exe,cwd,fd/,maps}`, `mounts`, `meminfo`, `uptime`,
  `cpuinfo`, `version`, `filesystems`), sysfs (`/sys/devices/system/cpu/{online,possible,
  present}`) and devpts. `may_inspect` guards `environ`, `maps`, `fd/`, `exe` and `cwd`.
- BusyBox: line editing with history and Tab completion, ash job control, `setsid`, `stty`,
  `ps`, `sleep`. `/init` runs the shell with `setsid -c /bin/sh`.
- Tests: the boot test types Ctrl-C on a sleeping job, Ctrl-Z, `jobs`, `fg` and Ctrl-C again
  (multi-step typing in `xtask`); new C tests compared with the host: `termios` (through a
  pty), `session`, `jobcontrol`, `poll` (with the registration race), `proc`; a kernel
  self-test for `TIOCSTI`.
- Tests: 20 boots pass; 23 C programs give the host's results; no frames or heap bytes
  leaked over two more rounds. The release build boots; `ps`, `stty -a`, `/proc`, `/sys`
  and `exit` work in the shell.
- Docs: security.md (TIOCSTI, `/proc` of other processes, no kernel addresses), roadmap
  (P2 done; the test desktop ladder in stages 6–7), decisions, vfs.md ("As built in P2").

- Found by the host comparison and fixed: the `ioctl` request is an `unsigned int`
  (musl passes `TIOCGPTN` sign-extended); `setpgid(-1, 0)` is `EINVAL` (the group defaults
  to the pid first); synthetic directories are not kept in the dentry cache, so
  `/dev/pts/N` of a closed pty is `ENOENT`, not a stale node.
- The user-program tests print how long each program took (debug log). `fpu` yields 1000
  times per process instead of 3000: with five new tests, three rounds no longer fit the
  90 s boot timeout.

### Different from the plan

- On a pty master, `TCGETS`/`TCSETS` act on the slave's settings, as Linux's
  `tty_mode_ioctl` does (found by the host comparison); the master has no settings of its own.
- Raw input becomes a finished line when canonical mode is switched on (Linux's
  `n_tty_set_termios`), not the line being edited.
- Tests that need job control run in a child that leads a new group: in OchraOS the kernel
  starts test programs as session leaders without a parent, whose group is orphaned, so
  `SIGTSTP` would rightly not stop it.
- Deviations from Linux are listed in decisions.md (2026-11-24): copies of `cmdline` and
  `environ`, plain symbolic links in `/proc/<pid>/fd`, `maps` from the page tables, no CPU
  times, no flush of the pty master's output on a signal character.

### Broken / open

- The serial console reports a 0×0 window until something sets it (as Linux's serial ports).
- `/proc/<pid>/fd/N` links cannot be opened for pipes; no `/proc/<pid>/task`, no `stat`
  times.
- `sched_yield` costs about 1.5 ms under KVM when several processes yield (the `fpu`
  test took 22 s for 15000 yields); to look into with the scheduler.
- `poll` timeouts are only as precise as the 10 ms tick; `poll` does not restart with the
  time left after a stop (Linux uses a restart block there too).
