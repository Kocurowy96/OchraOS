# 2026-11-23

## Stage 2, P4: signals and BusyBox (pitstop P4)

P3 (`f04522f`) was pushed and green in CI at the start of the session.

### Done

- Signals (`kernel/src/signal.rs`, `kernel/src/syscall/signal.rs`):
  - `rt_sigaction`, `rt_sigprocmask`, `rt_sigpending`, `rt_sigsuspend`, `pause`, `kill`,
    `tkill`, `tgkill`, `rt_sigreturn`;
  - delivery on every return to user mode: a new hook in `ochra-frame`
    (`set_return_handler`), called after syscalls, interrupts and exceptions;
  - Linux's `rt_sigframe` on the user stack, with the `fxsave` state; handlers start with a
    clean x87/SSE state; `SA_NODEFER`, `SA_RESETHAND`, `SA_RESTART`;
  - interruptible waits (`WaitQueue::wait_interruptible`) for pipes, the console, `wait4`;
    `ERESTARTSYS`/`ERESTARTNOHAND` become a restart or `EINTR`;
  - CPU faults send `SIGSEGV`/`SIGFPE`/… (handlers can catch them; blocked or ignored still
    kills); `SIGPIPE` on a write without readers; `SIGCHLD` with the child's status; no
    zombies when the parent ignores `SIGCHLD`; init is protected from default actions.
- `ochra-frame`: `UserContext::registers`/`set_registers` (flags filtered), `task::fpu_state`
  and `set_fpu_state` (MXCSR filtered).
- Files and paths (`kernel/src/syscall/paths.rs`): `open`, `openat`, `lseek`, `pread64`,
  `stat`, `fstat`, `lstat`, `newfstatat`, `access`, `faccessat`, `faccessat2`, `getcwd`,
  `chdir`, `fchdir`, `readlink`, `readlinkat`; `getuid`/`geteuid`/`getgid`/`getegid` (0).
  The initramfs now has directories, symbolic links and device nodes (`/dev/null`,
  `/dev/console`); processes have a current directory.
- `execve` runs `#!` scripts.
- BusyBox 1.38.0 (`xtask/src/busybox.rs`, `userspace/busybox.config`): built from a pinned
  Git commit against our musl, reproducibly; applets as symbolic links in `/bin`. Shared Git
  pinning for musl and BusyBox moved to `xtask/src/git.rs`. CI caches the BusyBox build.
- `/init` is now `userspace/init.sh` (`init.c` removed): it checks pipes, command
  substitution, arithmetic, functions, subshells, a background job, `trap`, SIGPIPE ending
  `yes`, a here-document, then runs an interactive shell in a loop. The boot test types two
  commands into that shell (`echo shell got $((6 * 7))`, `exit 3`).
- Tests (20 boots, 15 C programs compared with the host): new `signal`, `signal_process`,
  `paths`. The leak check now also compares heap usage between rounds.
- Fixes found on the way:
  - RFLAGS.AC is cleared on every kernel entry (a user program could set it and switch SMAP
    off for the interrupt handler);
  - kernel stack slots are reused (a page table leaked every 32 tasks);
  - the forked child's saved registers (`Box<ExceptionFrame>`, 176 bytes) and the process
    record leaked, because they were held across functions that never return.
- Release build boots and runs commands in the interactive shell.

### Broken / open

- No `getdents64` yet: `echo *` finds nothing. Directory reading comes with the VFS.
- No terminal control (`TCGETS`…): ash runs without line editing and without job control;
  Ctrl-C sends nothing.
- Real-time signals are not queued; no `sigaltstack`; stop signals are ignored.
